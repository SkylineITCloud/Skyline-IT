# Women's safety transition — reuse of the existing pages

24 October 2026. User-selected source: the parent Mzansi Connect folder under Skyline IT/Subsidies, including Product/Livestock tracker. This is distinct from the earlier desktop copy and from the nested Mzansi-Connect Git checkout. A read-only inspection showed richer existing firmware/hardware/server files; no conclusion from the earlier copy is used as proof about this newer hardware.

## Product direction

Centre women's agency, everyday journeys and understandable control over location sharing. Preserve South African identity, forest-green/gold branding and the existing page layouts. Address women, students and commuters without making individuals responsible for preventing abuse or promising a device can guarantee safety. No survivor stories, endorsements, partnerships, safety outcomes or service providers are fabricated.

Pendant, Wristband and Clip share the proposed emergency/permission model. Exact radio, battery, dimensions, charger, water resistance, two-way calling and tamper detection remain engineering decisions. All three user-supplied graphics and the generated family board are shown as concept art with adjacent status notes. Text embedded in those images, including seven-day runtime/IP67/calling/instant-alert claims, is not accepted as a validated specification.

| Earlier tested safety prototype API | Added separately under server/safety, integrated into local preview; all notification delivery simulated |

The old API names and field names may remain in historical source. A human safety model requires ownership, consent, scoped contacts, event lifecycle, replay protection and delivery evidence; renaming animals to women in SQL would not supply those protections. New development data is separate. Legacy endpoints are not mounted by the new safety preview.

## Verification and remaining gates

Validate page links/assets, JavaScript syntax, the adapted browser interactions and restricted static serving; preserve existing backend permission/idempotency tests. Record results in the merge output report. Web previews are not hardware demonstrations. The original Android project is not silently replaced with the earlier debug APK. Before connecting real wearables or people: reconcile physical revision, operator/SIM/antenna choices, target firmware drivers, identity/pairing/recovery, actual notification providers, retention/deletion, user research, security review and applicable approvals.

No public website was deployed, no marketing message sent, and no production record changed as part of this merge. Local start-safety-preview launchers provide the reviewable integration.
